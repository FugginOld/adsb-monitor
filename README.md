# ADS-B Stack Monitor

A self-hosted web dashboard for monitoring an ADS-B receiver station. Shows live feeder health, signal quality, uptime history, version status, and lets you configure and restart services — all from one page.

---

## What it does

| Area | Details |
|---|---|
| **Live status** | Active / down badge for every feeder and service, with last-seen time |
| **Data-flow alerts** | Flags a feeder that is running but has sent no data for 5 minutes (upload disconnected, lost input, stalled client): amber "no data" badge plus a banner line |
| **Uptime history** | 7-day daily bars + aggregate % per service, backed by SQLite |
| **Dual-band** | 1090 MHz ADS-B + 978 MHz UAT on two RTL-SDRs, merged onto one map |
| **Per-band signal** | 1090 block (RSSI / SNR / noise) and 978 block (RSSI), shown only for present bands; Airspy block hidden when absent |
| **readsb deep stats** | Aircraft count, message rate, range, signal metrics |
| **Version checking** | Current vs latest for each stack component |
| **Settings** | Per-SDR gain + bias-tee (1090 / 978), sharing keys, lat/lon/altitude, receiver options in-browser |
| **Log streaming** | Live tail of any feeder's systemd journal or Docker log (with Copy), plus a whole-system journal window in Settings |
| **Service control** | Restart any service (admin port only) |
| **Backup / restore** | Download config or graph data (collectd RRDs); import either back |

## Architecture

`run.py` is the process entry point; it imports `app.py` (Flask app +
config globals) which registers the `routes/*.py` Blueprints (thin HTTP
glue) backed by `system/*.py` (business logic — Host seam, init adapter,
config store, uptime ledger, feeder probe, SDR settings, version checking,
log streaming, background poller). Full breakdown, module-by-module and
route-by-route: **[ARCHITECTURE.md](ARCHITECTURE.md)**.

### Two ports

| Port | Purpose |
|---|---|
| `5000` (admin) | Full access — settings writes, service restarts, backup. Password login, LAN and Tailscale clients only |
| `5001` (read-only) | Status + stats only — safe to expose via reverse proxy. No login |

Configurable via `ADMIN_PORT` / `READONLY_PORT` environment variables.

The admin port refuses (403) any client outside loopback, the private LAN ranges
and Tailscale (`100.64.0.0/10`, `fd7a:…`), whatever interface the request arrives
on. Set `ADMIN_ALLOW_NETS` to change that: comma-separated CIDRs, `private` for
the default set, or `any` to turn the check off (e.g.
`ADMIN_ALLOW_NETS=private,203.0.113.0/24`). Both ports listen on every interface
by default; `ADMIN_BIND` / `READONLY_BIND` take a comma-separated address list.
The allow-list is the default rather than a fixed bind list because the LAN
address comes from DHCP and Tailscale may come up after the monitor starts.

### Admin login

The admin port asks for a password and stays **locked until one is set**:

```
sudo /opt/adsb-monitor/venv/bin/python /opt/adsb-monitor/run.py set-password
```

It prompts twice (at least 10 characters), takes effect without a restart, and
logs out every existing session. The password is stored hashed in
`admin_auth.json` (mode 0600, next to `feeders.ini`, never included in config
backups). A login lasts 30 days (cookie `adsb_monitor_admin`, HttpOnly,
SameSite=Strict); "Log out" ends it. After 5 wrong passwords from one address,
logins from it are refused for 15 minutes. Forgot it? Run the command again.

The admin port is plain HTTP, so only use it on your LAN or over Tailscale/VPN;
expose only the read-only port to the internet.

### Feeder kinds

`feeders.ini` declares each monitored unit as either:

- `[service:<unit>]` — a systemd unit or OpenRC service
- `[docker:<container>]` — a Docker container

### Init system support

At startup `detect_init()` probes the host and selects the right adapter:

| Init system | Adapter | Detection |
|---|---|---|
| systemd | `SystemdAdapter` | `systemctl --version` succeeds |
| OpenRC (Alpine / minimal SBC) | `OpenRCAdapter` | `rc-service --version` succeeds |
| Unknown | `NullAdapter` | service control endpoints return a clear error |

### Supported SDRs

| SDR | Decoder |
|---|---|
| Airspy Mini | airspy_adsb, 6 MSPS |
| Airspy R2 | airspy_adsb, 12 MSPS |
| RTL-SDR Blog V4 / generic RTL2832U | readsb |
| FlightAware Pro Stick / Plus | readsb |
| Nooelec NESDR SMArt / SMArTee | readsb |
| SDRplay RSP1A / RSPdx | SDRplay API + dump1090 (partly manual) |
| **2× RTL-SDR (dual-band)** | readsb (1090) + dump978-fa (978 UAT), merged on one map |

## Files

```
run.py              Process entry point (imports app.py, starts the server)
app.py              Flask app + config globals; registers routes/*.py
system/             Business logic, no Flask imports — see ARCHITECTURE.md
routes/             Flask Blueprints (thin HTTP glue) — see ARCHITECTURE.md
feeders.ini         Feeder declarations (auto-generated by installer)
history.db          SQLite uptime + metrics history (auto-created)
admin_auth.json     Admin password hash + session key (run.py set-password)
static/index.html   Single-page frontend (markup only)
static/app.css      Dashboard styles
static/js/          Dashboard scripts: core, status, settings, logs, init (+ login.js)
static/login.html   Admin-port login page
installer/
  install-stack.sh  Full TUI installer
  update-stack.sh   Update wiedehopf components + redeploy monitor
  uninstall.sh      TUI removal checklist
  lib.sh            Shared helpers (pkg mgr, init detection, TUI bootstrap)
  detect-sdr.sh     USB-ID SDR detection
  generate-feeders-ini.sh  Writes feeders.ini from installed services
```

## Requirements

- Python 3.11+ (Debian / Raspberry Pi OS bookworm or newer)
- `flask` + `psutil` (`pip install flask psutil`)
- `sqlite3` (stdlib)
- systemd **or** OpenRC (service control); monitor-only mode works without either
- **Dual-band (978 UAT) only:** `dump978-fa` + `skyaware978` (built by the installer),
  `soapysdr-module-rtlsdr`, and `rtl-sdr` for `rtl_test` / `rtl_eeprom` / `rtl_biast`.
  See [CREDIT.md](CREDIT.md) for the full list.
